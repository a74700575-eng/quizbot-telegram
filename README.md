# 🎮 بوت مسابقات تليجرام (نظام الفرق)

## التشغيل
1. اعمل بوت من @BotFather وخد الـ Token.
2. اعرف رقم حسابك من @userinfobot (ده الـ ADMIN_ID).
3. انسخ `.env.example` باسم `.env` وعبّي القيم. لتنسيق الأسئلة عبر Gemini استخدم `AI_PROVIDER=gemini` مع `AI_API_KEY` واسم نموذج متاح مثل `gemini-3.1-flash-lite` (اختياري، وقد تُحسب رسوم استخدام). للمزودات المتوافقة مع OpenAI استخدم `AI_PROVIDER=openai`.
4. شغّل (محتاج Python 3.10+):
```bash
python -m venv venv && source venv/bin/activate      # على ويندوز: venv\Scripts\activate
pip install -r requirements.txt
python bot.py
```
أو بـ Docker (الأفضل للاستضافة): `docker compose up -d --build` — قاعدة SQLite المحلية بتتحفظ في volume.

> ⚠️ **قاعدة البيانات:** محليًا يستخدم البوت SQLite. على Railway يُفضّل ربط PostgreSQL عبر `DATABASE_URL`؛ أو استخدم SQLite مع Volume واجعل `DB_PATH` داخله (مثل `/data/quizbot.db`). شغّل **نسخة واحدة فقط** من البوت لأن حالة المسابقة الحية في الذاكرة.

## نجم الساحة اليوم

يستخدم اللاعبون الأمر `/arena` أو زر **⭐ نجم الساحة اليوم** لعرض ترتيب كل الفرق حسب نتائج المسابقات التي بدأت في اليوم الحالي حسب `TIMEZONE` (القاهرة افتراضيًا). نقاط الإجابات الصحيحة تشمل مكافأة السرعة، ثم تُستخدم الإجابات الصحيحة ومكافأة السرعة لكسر التعادل. يظهر النجم/النجوم في الأعلى، وتُعرض الفرق في صفحات من 10 فرق حتى يمكن تصفح القائمة كاملة. يتجدد الترتيب تلقائيًا مع بداية يوم جديد حسب `TIMEZONE`.

## الأسئلة والتصويت والنقاط

يستطيع الأدمن إضافة صورة مخصصة أثناء إنشاء كل سؤال، أو تضمين رابط صورة عند الاستيراد. عند عرض السؤال تظهر الصورة (إن وُجدت) مع نص السؤال وأزرار اختيارات خضراء؛ زمن السؤال الافتراضي 60 ثانية، ويمكن للأدمن تخصيص زمن سؤال بعينه. بعد انتهاء الوقت يظهر الشرح الذي أدخله الأدمن. كل إجابة صحيحة تكسب صاحبها نقاط السؤال ومكافأة السرعة، حتى لو لم يتفق الفريق كله. ويكسب الفريق نقاطه ومكافأة السرعة الإضافية فقط إذا صوّت **كل أعضائه الحاليين** للإجابة الصحيحة. يمنع حذف الأسئلة أثناء مسابقة جارية؛ ويمكن تنظيف بنك الأسئلة من لوحة الأدمن بعد انتهائها.

## النشر على Railway

1. أنشئ Service من مستودع GitHub؛ Railway يكتشف `Dockerfile` الموجود في جذر المستودع ويستخدم أمر التشغيل `python bot.py`. اترك **Root Directory** فارغًا/على جذر المستودع؛ إذا استخدمت مسار Dockerfile مخصصًا فاضبط `RAILWAY_DOCKERFILE_PATH` وفق [توثيق Railway](https://docs.railway.com/builds/dockerfiles). اختَر خدمة مستمرة (Worker)، مش Cron؛ البوت لا يحتاج Public Domain أو Port لأنه يتصل بتليجرام عبر polling. راجع [دليل أوامر التشغيل](https://docs.railway.com/deployments/start-command) و[اختيار Worker](https://docs.railway.com/guides/cron-workers-queues).
2. في تبويب **Variables** لخدمة البوت، اربط متغير PostgreSQL باستخدام اسم خدمة قاعدة البيانات كما يظهر في مشروعك. مثال إذا كان اسم الخدمة `Postgres`:
   ```text
   DATABASE_URL=${{Postgres.DATABASE_URL}}
   ```
   Railway يدعم مراجع الخدمات بصيغة `${{SERVICE_NAME.VAR}}`؛ راجع [توثيق Variables](https://docs.railway.com/variables) و[توثيق PostgreSQL](https://docs.railway.com/databases/postgresql). غيّر `Postgres` إذا كان اسم خدمة قاعدة البيانات مختلفًا. البوت ينشئ الجداول والترقيات المطلوبة تلقائيًا عند بدء التشغيل.
3. أضف بقية المتغيرات من تبويب **Variables** في Railway (لا تضع الأسرار في GitHub):
   ```text
   BOT_TOKEN=<توكن جديد من BotFather>
   ADMIN_IDS=<Telegram user ID للأدمن>
   AI_PROVIDER=gemini
   AI_API_KEY=<Gemini API key>
   AI_MODEL=gemini-3.1-flash-lite
   TIMEZONE=Africa/Cairo
   ```
   عند استخدام PostgreSQL لا تحتاج إلى `DB_PATH` أو Volume لقاعدة البيانات. ولو اخترت SQLite بدلًا منها، اربط Volume على `/data` واضبط `DB_PATH=/data/quizbot.db`؛ Railway يركّب الـVolume عند تشغيل الخدمة حسب [توثيقه](https://docs.railway.com/volumes).
4. ابدأ بنسخة واحدة فقط لأن حالة المسابقة النشطة موجودة في ذاكرة العملية. خذ نسخًا احتياطية دورية من PostgreSQL، وتجنب Restart وقت التصويت إن أمكن.

قاعدة PostgreSQL الجديدة تبدأ فارغة؛ لا ينقل البوت بيانات SQLite القديمة تلقائيًا. أعد إضافة الفرق والأسئلة، أو اطلب إعداد عملية ترحيل مستقلة إذا كانت لديك بيانات قائمة.

**استعادة المسابقة:** لو أعيد تشغيل الخدمة أثناء مسابقة، يحفظ البوت النتائج المكتملة ويرسل للأدمن خيار استكمال؛ السؤال الذي انقطع يُعاد من بدايته. تحديثات Telegram المعلّقة عند بدء التشغيل تُسقط حاليًا، لذلك قد تضيع أصوات/رسائل وصلت أثناء الانقطاع. PostgreSQL يحفظ بيانات المسابقة المكتملة، لكنه لا يمنع انقطاع الخدمة أو فقد التحديثات المعلّقة.

## هيكل المشروع
```
bot.py                  نقطة التشغيل
quizbot/
  config.py             الإعدادات ومتغيرات البيئة
  db.py                 SQLite محليًا أو PostgreSQL على الاستضافة + ترقية القاعدة
  state.py              حالة المسابقة الشغالة (في الذاكرة)
  scoring.py            حساب الأغلبية والمكافأة والترتيب (بدون تليجرام)
  teams.py              الفرق والأعضاء
  board.py              لوحة الترتيب
  questions.py          بنك الأسئلة + استيراد JSON/HTML
  engine.py             محرك المسابقة (المؤقتات، التصويت، النتايج، الإيقاف/الاستكمال)
  ui.py                 الأزرار الملونة وأدوات الإرسال
  handlers_user.py      أوامر المستخدمين ونقاش الفريق
  admin/                لوحة الأدمن
    common.py             القائمة الرئيسية والثوابت
    questions.py          عرض/إضافة/تعديل/استيراد الأسئلة
    contest.py            بدء المسابقة، الحالة، الترتيب، السجل، التصدير
    teams.py              إدارة الفرق + رسالة للجميع
    settings.py           الإعدادات
    router.py             توزيع الأزرار
  app.py                تجميع البوت
tests/                  اختبارات (pytest)
```
الاختبارات: `pip install -r requirements-dev.txt && pytest`

## أوامر المستخدم
`/start` `/join CODE` `/createteam` `/team` `/leave` `/top` `/help`

يستطيع الأدمن إنشاء الفرق من لوحة التحكم أو `/newteam`، كما يستطيع أي مستخدم غير منضم إنشاء فريق من `/createteam` أو زر **إنشاء فريق جديد**؛ منشئ الفريق يصبح قائده ويحصل على كود ورابط دعوة. حفاظًا على انضمام كل مستخدم لفريق واحد فقط، يجب على العضو مغادرة فريقه الحالي قبل إنشاء فريق آخر. ويمكن للمستخدم بدلًا من ذلك إدخال كود فريق عند `/start` أو استخدام `/join CODE`. أول عضو ينضم إلى فريق أنشأه الأدمن يصبح قائده. أكواد الدعوة الجديدة من 8 خانات وتُحدّ محاولات الأكواد الخاطئة مؤقتًا؛ الأكواد الأقدم تظل صالحة.

رسائل نقاش الفريق تُحوّل كرسائل مُعاد توجيهها من حساب العضو، ليظهر اسم المرسل الأصلي وفق إعدادات الخصوصية في تيليجرام. البوت لا ينتحل حساب العضو ولا يرسل بصفته.

## أوامر الأدمن
`/admin` لوحة التحكم الكاملة · `/addq` إضافة سؤال سريع · `/aiimport` تنسيق مجموعة أسئلة بالذكاء الاصطناعي

## نظام النقاط
- كل إجابة صحيحة تمنح اللاعب نقاط السؤال ومكافأة السرعة الفردية؛ ويظهر رصيده بعد انتهاء السؤال.
- يحصل الفريق على نقاط إضافية في لوحة ترتيب الفرق فقط إذا أجاب **كل أعضائه الحاليين** الإجابة الصحيحة. عدم التصويت أو اختيار مختلف يعني عدم تحقق إجماع الفريق.
- **مكافأة السرعة:** إذا تحقق إجماع الفريق الصحيح، يحصل الفريق أيضًا على مكافأة سرعة حتى `speed_bonus`% (افتراضي 50%)، تقل كلما تأخر آخر عضو في الإجابة.

## التحكم أثناء المسابقة
⏭ إنهاء السؤال الآن · ⏸ إيقاف مؤقت/▶️ استئناف (الوقت المتبقي بيتحفظ) · 🖐 **التالي يدوي** (الأدمن هو اللي يفتح السؤال التالي) ·
⏹ إيقاف نهائي (بعد تأكيد). العدّاد الحي بيتحدّث في رسايل الأسئلة كل `tick` ثانية.

## أدوات إضافية
- 👑 **تغيير القائد:** قائد الفريق (صوته بيحسم التعادل) يقدر يسلّم القيادة لأي عضو من `/team`.
- ✏️ **تعديل الأسئلة:** من الأسئلة ← السؤال ← تعديل (النص، الشرح، الوقت، النقاط، الصورة). `-` بتمسح القيمة.
- 🗂 **سجل المسابقات:** آخر 10 مسابقات بالفايز، ومنها ترتيب كل مسابقة وتصدير CSV لأي مسابقة قديمة.
- ⚠️ **إشعار الأخطاء:** لو حصل خطأ غير متوقع الأدمن بيوصله تنبيه (مرة كل 10 دقايق لكل نوع). التوقيت بيتظبط بـ `TIMEZONE` (افتراضي `Africa/Cairo`).

## استكمال بعد انقطاع
لو البوت اتعاد تشغيله أثناء مسابقة، الأدمن بيوصله إشعار وزرار **♻️ استكمال المسابقة** — بتكمل من السؤال اللي كان مفتوح (بيتعاد من الأول)، ونقاط الأسئلة اللي خلصت محفوظة.

## استيراد الأسئلة (JSON أو HTML)
**JSON:**
```json
[{"question":"عاصمة مصر؟","options":["القاهرة","الإسكندرية","أسوان"],"answer":1,
  "explanation":"القاهرة","time":45,"points":10,"image":"https://example.com/cairo.jpg"}]
```
`answer` = رقم الإجابة الصحيحة من 1. الحقول `explanation` و`time` و`points` و`image` اختيارية.

**HTML:** كل سؤال داخل عنصر `class="q"`:
```html
<div class="q" data-answer="2" data-time="45" data-points="10" data-image="https://..."><h3>عاصمة مصر؟</h3><ol><li>أسوان</li><li>القاهرة</li></ol><p class="exp">القاهرة هي العاصمة</p></div>
```
الإجابة الصحيحة: `data-answer` (من 1) أو `class="correct"` على الـ `<li>`. الأسئلة المكررة بتتجاهل، والأخطاء بتتعرض برقم السؤال وسببها.

## تنسيق الأسئلة بالذكاء الاصطناعي
من لوحة الأدمن اختر «تحويل نص إلى كويز بالذكاء الاصطناعي» أو `/aiimport`، ثم الصق الأسئلة والاختيارات والإجابات الصحيحة، أو أرسل ملف `.txt` (حد أقصى 50 سؤالًا و20,000 حرف في الدفعة). Gemini يستخدم Google GenAI SDK الأصلي عند ضبط `AI_PROVIDER=gemini`. يتحقق البوت من تسلسل مواضع الأسئلة ومن وجود مقتطف مطابق من النص الأصلي، ويعرض المعاينة مع الإجابة المحددة. أي إجابة ناقصة/ملتبسة أو ترتيب/مصدر غير قابل للتحقق يذهب للمراجعة ولا يُضاف. **لا تُحفظ أسئلة قبل ضغط الأدمن «أضف» بعد مراجعة المعاينة.** النص يُرسل لمزود AI الذي تضبطه في `AI_API_KEY`؛ راجع سياسة الخصوصية والتكلفة لدى مزودك.
